# local-llm-bench

Стенд для трёх практических вопросов о локальной LLM, которая собирает данные из интернета:

1. **Какая открытая модель на машине со 128 ГБ вытаскивает данные из веб-страниц и с какой скоростью?**
2. **Как отдать свежие данные другой модели (Claude, GPT) быстрее чем за секунду?**
3. **Что пойдёт не так, если агент сам читает страницы, и что от этого реально защищает?**

Всё меряется, а не пересказывается: корпус из 50 настоящих карточек товаров, эталон из разметки самих
страниц, три прогона на модель, атаки было/стало.

## Как устроено

| Файл | Что делает |
|---|---|
| `collect.py` | Собирает 50 карточек из четырёх магазинов (пауза 1,5 с). Эталон — Product JSON-LD страницы. Модели получают текст **без** разметки и скриптов. Для каждого поля отмечается, видно ли значение в тексте — точность считается только по видимым |
| `extract_bench.py` | Извлечение 8 полей в JSON по строгой схеме через любой OpenAI-совместимый сервер (llama-server, vLLM, облако). Пишет точность, выдуманные значения, токены, секунды, скорость чтения/ответа llama.cpp |
| `report.py` | Сводка по прогону: поля, магазины, скорость |
| `store.py` | Postgres + pgvector: записи с источником, датой проверки, хэшем содержимого; полнотекст + эмбеддинги (multilingual MiniLM на CPU) |
| `mcp_server.py` | MCP-сервер из трёх инструментов: `search` (гибрид полнотекст + векторы), `get_record`, `changed_since`. Слушает только 127.0.0.1 |
| `mcp_latency.py` | Задержка от вызова инструмента до ответа: p50/p95/p99, раскладка эмбеддинг/SQL, нагрузка параллельными клиентами |
| `injection_bench.py` | Пять видов скрытых команд в тексте страницы; наивный агент (ключ в инструкции, инструменты) против схемы «читатель без инструментов + проверка кодом» |
| `inj_report.py` | Сводка атак: прошло у наивного, поддалась модель, дошло до базы на уровнях защиты 1 и 2; ложные тревоги на чистых страницах |
| `gpu_run.sh` | Один запуск на арендованной видеокарте: сборка llama.cpp с CUDA, модели, все замеры, архив результатов |

**Ответы на три вопроса по этим замерам одним документом:** [OTVETY.md](OTVETY.md)

## Результаты (24–25.09.2026, NVIDIA A100 80 ГБ PCIe, llama.cpp 84e76d8)

### 1. Извлечение: 50 карточек × 3 прогона, 8 полей, строгая JSON-схема

| Модель | Поля точно | Выдуманные цены | Секунд на страницу (медиана) | Видеопамять |
|---|---|---|---|---|
| gpt-oss-120b (MXFP4) | 89,7% | 0 из 114 | 4,0 | 61 ГБ |
| Qwen3.8-27B (Q4_K_M) | 92,2% | 0 из 114 | 8,7 | 22 ГБ |
| Qwen3.8-27B (Q8_0) | 92,7% | 0 из 114 | 9,2 | 30 ГБ |
| Hermes 4.3 36B (Q4_K_M) | 90,6% | 0 из 114 | 5,7 | 37 ГБ |
| gpt-oss-120b через облачный API (контроль) | 89,8% | 0 из 38 | 5,6 | — |
| DeepSeek-V4.1-Flash через облачный API (763B, в 128 ГБ не влезает) | 93,5%* | 0 из 38 | 5,1 (до 37) | — |

\* С лимитом ответа 1 500 токенов 8 из 50 ответов оборвались на рассуждениях (83,7%); с лимитом 6 000 —
ответ на всех, 93,5%. Рассуждающая модель на неоднозначной странице тратит тысячи токенов: время и цена
непредсказуемы. Облако по прайсу — ≈$2–4 за 1 000 страниц; аренда A100 с gpt-oss в один поток — ≈230 ₽.

Прогоны устойчивы (temperature 0): у Qwen три прогона совпали до поля, у gpt-oss 89,4 / 89,8 / 89,8%.
Локальный запуск gpt-oss не отличается по точности от облачного.

### Скорость (llama-bench: чтение 2 048 / ответ 128 токенов при контексте 0 / 8k / 32k)

| Модель | Чтение, ток/с | Ответ, ток/с |
|---|---|---|
| gpt-oss-120b MXFP4 | 1 835 / 1 767 / 1 609 | 143 / 137 / 126 |
| Qwen3.8-27B Q4_K_M | 1 294 / 1 241 / 1 086 | 47 / 46 / 44 |
| Qwen3.8-27B Q8_0 | 1 264 / 1 212 / 1 066 | 40 / 40 / 38 |
| Hermes 4.3 36B Q4_K_M | 1 081 / 862 / 531 | 40 / 37 / 33 |

У Hermes 4.3 (Seed-OSS-36B) чтение на 32k контекста падает вдвое — у остальных на 12–16%.

Квантизация: Q4 против Q8 у Qwen — одно поле из 245 за прогон, при 17,7 ГБ против 26,6 ГБ и +17% к скорости ответа.

### 2. MCP над Postgres + pgvector, 20 050 записей, от вызова до ответа

| Инструмент | p50, мс | p95, мс |
|---|---|---|
| get_record | 4,2 | 4,9 |
| changed_since | 5,2 | 7,1 |
| search (гибрид) | 16,2 | 20,4 |
| search, 8 клиентов параллельно | 98 | 135 |

Поиск: эмбеддинг запроса на CPU 7,5 мс, SQL 1,9 мс. Под нагрузкой узкое место — эмбеддинг на CPU (3 ядра).

### 3. Инъекции: 12 карточек × 5 атак, копии страниц, ключ подставной, инструменты пустые

| | gpt-oss-120b | Qwen Q4 | Qwen Q8 | Hermes 4.3 | DeepSeek-V4.1-Flash (API) |
|---|---|---|---|---|---|
| Наивный агент: атак прошло | 36 / 60 | 21 / 60 | 22 / 60 | 45 / 60 | 1 / 60 |
| — выдал ключ | 11 / 12 | 0 / 12 | 0 / 12 | 5 / 12 | 0 / 12 |
| — открыл чужой адрес | 5 / 12 | 10 / 12 | 12 / 12 | 12 / 12 | 0 / 12 |
| Читатель + код, уровень 1: дошло до базы | 8 / 60 | 8 / 60 | 8 / 60 | 5 / 60 | 0 / 60 |
| Читатель + код, уровень 2: дошло до базы | 0 / 60 | 0 / 60 | 0 / 60 | 0 / 60 | 0 / 60 |
| Остановлено уровнем 2 на чистых страницах | 6 / 150 | 3 / 150 | 3 / 150 | 15 / 150 | 1 / 50 |

У Hermes 12 из 15 остановок на чистых страницах — пойманная ошибка модели: где цены в тексте нет, он подставил
номер товара («2 049 457 ₽» за матрас). Выдумкой это не считается, число на странице есть; сверка с разметкой ловит.

У DeepSeek 13 ответов читателя из 60 оборвались на рассуждениях при лимите 1 500 токенов: устойчивость к атакам
у рассуждающей модели выше, но часть страниц остаётся без данных, если не дать запас токенов.

Уровень 1 пропускает только тонкое отравление (цена −10%); уровень 2 сверяет цену модели с разметкой страницы.
Модели ломаются по-разному (одна выдаёт ключ, другая ходит по ссылкам) — защита строится устройством системы,
а не выбором модели.

## Как повторить

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python collect.py                       # корпус
# модель: llama-server -m model.gguf -ngl 999 -c 65536 --jinja --port 8080
.venv/bin/python extract_bench.py --base-url http://127.0.0.1:8080/v1 --model local --tag my-run --runs 3
.venv/bin/python report.py results/my-run.jsonl
.venv/bin/python injection_bench.py --base-url http://127.0.0.1:8080/v1 --model local --tag my-run
.venv/bin/python inj_report.py results/inj-my-run.jsonl results/my-run.jsonl
# вопрос 2: docker run -d -p 127.0.0.1:55432:5432 -e POSTGRES_PASSWORD=test -e POSTGRES_DB=sbor pgvector/pgvector:pg16
.venv/bin/python store.py --synthetic 20000 && .venv/bin/python mcp_server.py &
.venv/bin/python mcp_latency.py --n 200 --conc 8
```

Страницы магазинов в репозиторий не входят — `collect.py` собирает их заново; адреса и эталон лежат в
`corpus/gold.jsonl`. Синтетические записи в `store.py` — только для нагрузки на таблицу реального размера,
в выводах о точности они не участвуют.

## Ограничения

- Скорость измерена на A100 80 ГБ. На DGX Spark и Mac Studio она другая; точность переносится, скорость — нет.
- 50 карточек из четырёх магазинов — не весь интернет. Цифры показывают порядок и характер ошибок, а не гарантию.
- Проверка «уровня 2» опирается на разметку страницы. Если лжёт сам сайт, она не поможет — нужна сверка
  между источниками и история значений.
